Create a Tor-backed VPN-style gateway in minutes

pnb connect router installs Tor, enables IP forwarding, and sets NAT rules so your host (and optional LAN) route outbound traffic through the Tor network.

Read the full guide View the setup script

What you get

Tor transparent proxy

Tor listens on 9040 (TransPort) and 9053 (DNSPort), redirecting TCP and DNS traffic while mapping virtual addresses for non-exit-friendly destinations.

Hardened defaults

Firewall rules exempt Tor's own traffic, drop leaks, and persist via iptables-persistent, keeping the gateway online after reboots.

LAN friendly

Enable IP forwarding and optionally NAT a downstream interface so multiple devices can share Tor-backed egress.

Reversible changes

The existing torrc is backed up on first run, letting you revert if you need to restore prior settings.

Quick start

1) Inspect the script

Review scripts/pnb-connect-setup.sh to understand the iptables and Tor settings.

2) Run as root

Pass the interfaces you want to use. The script defaults to eth0 for WAN.

sudo EXTERNAL_IFACE=eth0 INTERNAL_IFACE=eth1 \
  scripts/pnb-connect-setup.sh
3) Verify Tor

Ensure Tor is healthy and that your egress IP is a Tor exit.

systemctl status tor
curl --socks5 localhost:9050 https://check.torproject.org/api/ip
4) Optional LAN config

Assign your LAN interface an address and DHCP so downstream clients use this host's gateway and DNS.

Safety notes

Understand Tor limits

Traffic leaving Tor exits can be deanonymized by malicious operators. Always prefer HTTPS and review your threat model.

Review firewall rules

iptables rules redirect TCP SYN packets and DNS queries to Tor. Validate the rules before production use.

Test in staging

Try the setup on a lab host first. Confirm routing and DNS behave as expected for your applications.
