Downloads

Build or fetch a clean OneOS rootfs for WSL.

Follow the official recipe to assemble a Debian-based archive, then import it with wsl --import. Configure mirrors, releases, and packages when you need to tailor the image.

Download build script Review build docs
Default build targets Debian bookworm, ships with sudo + apt, and compresses to oneos.tar.gz.
Quick build + import
sudo apt update \
  && sudo apt install -y debootstrap xz-utils \
  && sudo bash oneos/build-oneos.sh

# import into WSL
wsl --import OneOS $env:USERPROFILE\OneOS oneos.tar.gz --version 2
wsl -d OneOS

Prefer piping? curl -fsSL https://oneos.org/oneos/build-oneos.sh | sudo bash

Choose your path

Pick a preset or customize the archive.

Start from the stable defaults or tweak the bootstrap knobs to match your workflow.

Stable defaults

Minimal Debian bookworm image ready for WSL import.

  • Includes sudo, apt, and sensible locale/timezone defaults.
  • Produces oneos.tar.gz at the repo root after running the script.
  • Best for fresh workspaces or CI runners that need a predictable base.

Customize the build

Override environment variables to tune the archive:

  • ONEOS_RELEASE – pick a Debian suite (e.g., bookworm, bullseye).
  • ONEOS_MIRROR – point to your preferred Debian mirror.
  • ONEOS_PACKAGES – add packages at bootstrap time (e.g., git, ca-certificates).
  • ONEOS_TARBALL – change the exported archive name.

See oneos/README.md for every flag and example.

WSL import

Use the tarball anywhere you sign in.

1

Copy the archive to Windows

Move oneos.tar.gz to your Windows filesystem (e.g., $env:USERPROFILE\\OneOS).

2

Import into WSL

Run wsl --import OneOS $env:USERPROFILE\\OneOS oneos.tar.gz --version 2 from PowerShell or Windows Terminal.

3

Start your instance

Launch with wsl -d OneOS, then create users, install dotfiles, or rebuild whenever you need a fresh base.

Integrity and portability

Validate archives and share safely.

Keep your imported environments trustworthy when downloading or distributing OneOS tarballs.

Verify locally

Generate a checksum beside the archive and compare before importing:

sha256sum oneos.tar.gz > oneos.tar.gz.sha256
sha256sum -c oneos.tar.gz.sha256

Rebuild and refresh checksums whenever you regenerate the tarball.

Share within your team

Store the tarball in your artifact registry or on a network share. Keep the checksum file next to it so teammates can validate what they pull down.

For automated pipelines, publish oneos.tar.gz after the build job and import it in downstream steps.
