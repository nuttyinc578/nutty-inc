Minimal. Root-based. Built for WSL.

OneOS keeps Windows Subsystem for Linux lean and predictable.

Use the provided build script to assemble a clean Debian-based rootfs, import it into WSL, and start with an uncluttered environment you control.

Build and import Why OneOS?
Ship-ready defaults · Fast provisioning · No cruft
Quick build (Debian/Ubuntu host)
sudo apt update \
  && sudo apt install -y debootstrap xz-utils \
  && sudo bash oneos/build-oneos.sh

# import into WSL
wsl --import OneOS $env:USERPROFILE\OneOS oneos.tar.gz --version 2
wsl -d OneOS

Configure build variables via environment (e.g., ONEOS_RELEASE=bullseye). See docs for all options.

Get OneOS

Build locally, then import into WSL.

Run the build script on a Debian/Ubuntu host, then use the generated tarball with wsl --import.

1

Prepare your host

Install debootstrap and xz-utils. The script handles the rest.

2

Build

Run sudo bash oneos/build-oneos.sh (or fetch via curl -fsSL ... | sudo bash). Customize with environment variables like ONEOS_RELEASE, ONEOS_MIRROR, or ONEOS_PACKAGES.

3

Import into WSL

Use PowerShell: wsl --import OneOS $env:USERPROFILE\OneOS oneos.tar.gz --version 2, then start with wsl -d OneOS.

4

Stay updated

Run sudo apt update && sudo apt upgrade inside WSL to keep your environment current. Rebuild and re-import anytime to refresh the base image.

Make it yours

Customize the image with simple flags.

Environment variables change mirrors, releases, and packages without editing the script. Fork the repo to add bootstrap hooks if you need more.

Common knobs

  • ONEOS_RELEASE – choose the Debian suite (e.g., bookworm).
  • ONEOS_MIRROR – point to your nearest Debian mirror.
  • ONEOS_PACKAGES – add extra packages during bootstrap.
  • ONEOS_TARBALL – name the exported archive.

See oneos/README.md for the full matrix of options.

Example: customized build

ONEOS_RELEASE=bookworm \ 
ONEOS_MIRROR=https://deb.debian.org/debian \ 
ONEOS_PACKAGES="curl ca-certificates git" \ 
sudo bash oneos/build-oneos.sh

Ideal for bootstrapping a dev-ready WSL instance with Git and TLS tooling already installed.

FAQ

Answers to common questions.

Why use OneOS instead of a prebuilt distro?

OneOS prioritizes control: you build from trusted sources, pick the release and packages, and avoid the bloat that comes with generic images.

Which hosts are supported for building?

Use Debian or Ubuntu hosts with debootstrap available. The build script pulls everything it needs and outputs a compressed tarball for WSL import.

How do I update an existing OneOS instance?

Inside WSL, run sudo apt update && sudo apt upgrade. For a fresh base, rebuild the tarball and re-import a new WSL distribution.

Is desktop usage supported?

OneOS targets headless or terminal-centric workflows. You can install GUI stacks after import, but the default image stays minimal to keep WSL fast.
